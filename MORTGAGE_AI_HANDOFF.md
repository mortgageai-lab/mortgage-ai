# Mortgage AI — handoff для Codex

## Зачем проект

**Mortgage AI** — внутренний помощник ипотечной команды Whitewill. Его первая задача — упорядочить работу со сделкой и документами клиента: создать сделку, собрать файлы в одном месте и дать команде понятную структуру. В дальнейшем система должна снижать ручную нагрузку, помогать с проверкой комплекта документов и давать руководителю прозрачность по процессу.

## Люди и роли

| Роль | Что делает в будущей системе |
| --- | --- |
| **Андрей, руководитель** | Видит сделки и их статусы, позже — отчётность, качество работы и узкие места процесса. |
| **Анастасия, менеджер** | Создаёт сделку, запрашивает и загружает документы, ведёт клиента по процессу. |
| **Клиент** | Передаёт необходимые документы менеджеру / в согласованный канал. |
| **Около 70 брокеров** | Важный источник консультаций и экспертизы; интеграция с ними не входит в текущий MVP. |

## Текущий процесс (как есть)

Документы и коммуникации по ипотечным сделкам могут быть распределены по разным чатам и папкам. Нужно вручную создавать структуру под клиента, контролировать, чего не хватает, и искать материалы. Это затрудняет передачу сделки между сотрудниками и контроль со стороны руководителя.

## Целевая система

Основной пользовательский путь:

```text
Telegram
  → бот Mortgage AI
  → сделка и папка клиента в Google Drive
  → загрузка и хранение документов в нужной структуре
  → (позже) распознавание, проверка комплекта и качества, статусы и аналитика
```

Telegram — удобная точка входа для команды. Google Drive — первое хранилище документов. Бот не должен хранить секреты или документы в GitHub.

## Текущая рабочая версия — 12 августа 2026

Локальный MVP на Intel MacBook создан и проверен. В нём уже есть:

- запуск Telegram-бота на Python + `aiogram`;
- команда `/start_deal`, создающая папку сделки формата `ДД.ММ.ГГГГ ЧЧ-ММ-СС`
  и подпапку `Documents`;
- сохранение документов и фотографий из чата сделки;
- исключение документов, отправленных Андреем и Анастасией, по настройке
  `EXCLUDED_USERNAMES`;
- возможность вручную переименовать папку сделки без потери связи с чатом;
- личный модуль обратной связи для клиентов: оценка от 1 до 5 и комментарий,
  направляемый руководителю в Telegram;
- локальное OCR-распознавание и понятное переименование: паспорт, СНИЛС,
  справка 2-НДФЛ, свидетельства о заключении/расторжении брака и о рождении;
- обработка альбома фотографий паспорта как единого комплекта страниц;
- безопасное поведение для непонятных файлов: сохранить исходное имя, а не
  выдавать сомнительный результат.

Ограничения текущей версии: бот работает, только пока открыт Терминал и
выполняется `python bot.py`; документы находятся на данном Mac; проверка OCR
не заменяет ручную оценку качества и достоверности документов.

## Ближайший продуктовый этап

Создать карточку сделки: список необходимых документов, состояния
«получен / не получен / проверить», текущий статус сделки и базовые
напоминания. Это станет основой для утренней сводки, контроля зависших
клиентов и формирования пакета для банка.

## Следующий инфраструктурный этап — Google Drive и сервер

После карточки сделки подключить Google Drive и развернуть бота на
постоянно работающем сервере:

1. Настроить доступ бота к отдельному Google-аккаунту проекта.
2. По `/start_deal` создавать папку сделки в заранее выбранной корневой папке Drive.
3. Сохранять/показывать ID сделки и ссылку на созданную папку.
4. Добавить понятную структуру подпапок для документов.

Точный сценарий на этапе Drive:

```text
Анастасия → /start_deal в Telegram
Telegram → бот создаёт ID сделки
бот → создаёт папку сделки в Google Drive
бот → создаёт подпапки для документов
бот → возвращает подтверждение, ID и ссылку на папку
Анастасия/клиент → передают документы
бот/менеджер → размещает файлы в папке сделки
```

## Известные документы физического лица

Перечень будет уточняться под банк и тип сделки. Базово следует предусмотреть категории:

- паспорт;
- СНИЛС / ИНН (если требуются банком);
- подтверждение дохода: справка 2-НДФЛ / по форме банка;
- подтверждение занятости: копия трудовой книжки, трудовой договор или сведения о работе;
- выписки по счетам / подтверждение первоначального взноса;
- документы по текущим кредитам и обязательствам;
- документы супруга/супруги и согласия — когда применимо;
- документы по объекту недвижимости — на соответствующем этапе сделки.

Не закладывать сейчас автоматическую проверку этого списка: в v0.1 он нужен только как ориентир для структуры папок.

## Принятые решения и безопасность

- Строим систему слоями: текущий локальный бот, затем карточка сделки, затем
  Google Drive и постоянно работающий сервер, после этого — более сложная
  автоматизация.
- Локальное OCR уже используется; OpenAI для распознавания документов не
  подключается. Извлечение и хранение персональных данных откладывается до
  защищённого общего хранилища.
- Секреты хранятся локально в `.env`: как минимум `BOT_TOKEN`, позднее — учётные данные Google.
- `.env` обязательно добавить в `.gitignore` **до первого коммита с настройками**.
- Никогда не коммитить в GitHub токены Telegram, API-ключи, пароли, `credentials.json`, `token.json` или реальные документы клиентов.
- В репозиторий можно добавить безопасный шаблон `.env.example` без настоящих значений.

## Пока не входит в текущую версию

- OpenAI и любые LLM-функции;
- извлечение персональных данных из документов;
- автоматическая проверка качества и комплектности;
- статистика, дашборды и отчётность;
- новости и консультационный модуль для брокеров;
- полноценная база данных и многопользовательские права;
- облачный сервер/хостинг: первый запуск локальный.

## Безопасность — обязательные правила

- Секреты хранятся только в локальном `.env`: `BOT_TOKEN`, позднее доступ к
  Google Drive. Сам файл не отслеживается Git.
- В Git разрешён только `.env.example` без настоящих значений.
- Запрещено добавлять в Git реальные документы клиентов, папки `Deals/`,
  служебные данные `data/`, отчёты `outputs/`, файлы `credentials.json` и
  `token.json`.
- До извлечения и хранения персональных данных нужно перейти на общее
  защищённое хранилище, определить права доступа и резервное копирование.

## Дальнейшее развитие

- **Ближайшее:** карточка комплекта документов, статусы и напоминания.
- **После этого:** Google Drive, сервер 24/7, поиск документов и формирование

- **Далее:** извлечение данных, предзаполнение анкет, аналитика, база знаний
