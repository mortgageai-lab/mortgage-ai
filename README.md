# Mortgage AI — Telegram-бот для ипотечной команды

Рабочая первая версия внутреннего бота ипотечной команды Whitewill. Бот
создаёт локальную папку сделки, сохраняет документы клиентов, распознаёт
несколько типов документов и принимает отзывы клиентов в личном чате.

> Бот уже перенесён на сервер. Подключение Google Drive добавлено как
> безопасное зеркальное хранение: локальная копия на сервере остаётся первой,
> а в Drive отправляется вторая копия после одноразовой авторизации.

## Что потребуется

- macOS и Python 3.10+;
- токен созданного бота из BotFather;
- для работы в групповом чате: добавьте туда бота и в BotFather отключите
  Privacy Mode (`/setprivacy` → `Disable`).

Если macOS сообщает, что отсутствуют инструменты разработчика, установите их:

```bash
xcode-select --install
```

## Запуск

В Терминале перейдите в папку проекта и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и вставьте токен в одну строку без кавычек:

```text
BOT_TOKEN=ваш_токен_из_BotFather
```

Запустите бота:

```bash
python bot.py
```

После запуска один раз создайте закрытую группу `Mortgage Notifications`,
добавьте туда руководителя, менеджера и бота, затем выполните в ней
`/set_notifications`. Команду принимает только руководитель, указанный в
`MANAGER_USER_ID`. Остановить программу можно сочетанием `Ctrl+C` в Терминале.

Когда руководитель или менеджер добавляет бота в новый клиентский чат, сделка
создаётся автоматически, без `/start` и `/start_deal`:

```text
Deals/
└── Телеграмм ДД.ММ - ЧЧ:ММ/
    └── Документы из чата/
```

Бот запоминает связь чата и сделки в локальном файле `data/chat_deals.json`.
Он нужен только для работы текущего экземпляра и не содержит токенов. Новая
связь создаётся автоматически при добавлении бота. Старые сделки и их
папки `Documents` продолжают поддерживаться.

Папку сделки можно вручную переименовать в Finder, например в `Иванов Иван`.
Бот продолжит находить её и сохранять документы в `Документы из чата`.

## Приём документов

После создания сделки отправьте в тот же Telegram-чат файл как **документ**
или фотографию. В клиентском чате бот ничего не пишет и не ставит реакций.
Результат сохранения, распознавания или ошибка появляются только в
`Mortgage Notifications`, а файл — в `Документы из чата`.

Если посторонний пользователь добавит бота в другую группу, бот сразу выйдет,
не создавая сделку и не сохраняя документы. Добавлять его в рабочие группы
могут только постоянные Telegram ID из `MANAGER_USER_ID` и `TEAM_USER_IDS`.

Для приёма обычных файлов в групповом чате в BotFather должно быть отключено
Privacy Mode: `/setprivacy` → выберите бота → `Disable`.

## Фильтр документов команды

Документы и фотографии от указанных участников можно не сохранять. В `.env`
добавьте строку (без символа `@`):

```text
EXCLUDED_USERNAMES=Anastasia_ipoteka,andrey_ipoteka
TEAM_USER_IDS=числовой_id_Анастасии
```

Файлы от этих двух Telegram-юзернеймов будут пропущены, а файлы от остальных
участников чата сохранятся как обычно. Юзернейм можно изменить в Telegram,
поэтому для более строгой настройки бот также отвечает на `/my_id` и показывает
неизменяемый числовой Telegram ID отправителя.

## Отзывы клиентов

В личном чате бот работает как контроль качества для всех, кроме руководителя
и менеджера. Оценка от 1 до 5 сразу отправляется только руководителю в личный
чат с ботом и содержит имя, username и Telegram ID клиента. Если клиент позже
добавляет комментарий, бот обновляет то же личное уведомление. Один Telegram ID
может отправить не более трёх оценок за скользящие 24 часа; счётчик сохраняется
в `data/feedback_rate_limits.json` и переживает перезапуск. Добавьте в `.env`
числовой ID руководителя:

```text
MANAGER_USER_ID=1680647231
```

Закрытая группа `Mortgage Notifications` используется только для операционных
сообщений о папках, документах и ошибках. Отзывы туда не пересылаются.

## Распознавание документов

Бот локально проверяет присланные изображения и до двух первых страниц PDF.
Если файл распознан как российский паспорт, он переименовывается в
`Паспорт.pdf`. Бот намеренно не извлекает и не использует ФИО на этом этапе.
Документы других типов остаются с исходным именем. Для работы нужны Tesseract
OCR и русский языковой пакет (`rus`).
Перед распознаванием бот пытается автоматически исправить поворот страницы.
Для более устойчивого чтения он использует несколько режимов OCR и проверяет
как заголовок паспорта, так и характерную структуру страницы с данными.

Если клиент отправляет несколько страниц одним Telegram-альбомом, бот считает
их одним документом, объединяет OCR-текст страниц и сохраняет результат как
`Доверенность 1.jpg`, `Доверенность 2.jpg` или аналогично для другого типа.
Разные документы нужно отправлять разными альбомами.

## Распознавание СНИЛС

Бот также распознаёт СНИЛС — страховой номер индивидуального лицевого счёта:
современный документ, полную расшифровку названия и старое страховое
свидетельство обязательного пенсионного страхования. Распознанный
файл получает имя `СНИЛС.pdf` или `СНИЛС.jpg`. Фотографии с сильным наклоном,
бликами или закрытым текстом могут не распознаться и останутся с исходным
именем для ручной проверки. Для небольшого документа на большом белом скане
бот автоматически выделяет основную область перед OCR.

## Неопознанные документы

Бот даёт новое имя только документам, которые распознаёт уверенно. Неизвестные
или плохо читаемые файлы сохраняются с исходным именем. Для каждого файла OCR
имеет ограничение по времени, чтобы один сложный документ не задерживал
обработку остальных.

Форматы файлов пока не ограничиваются: например, ZIP сохраняется как обычный
файл, но не отправляется в OCR. Для защиты процесса действуют ограничения:

- до 25 МБ — файл сохраняется и поддерживаемый формат проходит OCR;
- от 25 до 50 МБ — файл сохраняется без распознавания;
- больше 50 МБ — файл не скачивается и не сохраняется;
- изображение больше 25 мегапикселей сохраняется без OCR;
- PDF распознаётся только по первым двум страницам;
- Telegram-альбом дополнительно проверяется по общему размеру.

В `Mortgage Notifications` всегда указывается имя файла и причина, например:
`Документ "archive.zip" сохранён без распознавания: формат .zip не поддерживает
распознавание`.

## Другие распознаваемые документы

Бот также распознаёт и именует: `Доверенность`, `Справка 2-НДФЛ`,
`Свидетельство о заключении брака`, `Свидетельство о расторжении брака` и
`Свидетельство о рождении`. Заголовок «Доверенность» имеет приоритет над
паспортными реквизитами, которые могут находиться внутри документа.

Распознавание основано на OCR и является вспомогательным: оно определяет тип
документа, но не подтверждает его юридическую достоверность, полноту или
актуальность. Нечёткие, обрезанные или необычно оформленные документы могут
остаться с исходным именем — это нормальный и безопасный результат.

## Безопасность

Настоящий `.env` уже исключён из Git. В репозитории хранится только безопасный
`.env.example` без токена. Также Git игнорирует папки `Deals/`, `data/` и
`outputs/`, а также будущие файлы доступа Google (`credentials.json`,
`token.json`). Папка `secrets/` с OAuth-ключом и токеном Google Drive также
исключена из Git.

## Google Drive на сервере

Интеграция использует отдельный рабочий Google-аккаунт и ограниченное
разрешение `drive.file`. Бот создаёт в его Google Drive собственную корневую
папку `Mortgage AI — Сделки (бот)` и внутри — папку каждой новой сделки и
`Документы из чата`. Доступ к уже существующим личным папкам Google Drive не нужен.

До завершения настройки `GOOGLE_DRIVE_ENABLED=false`: бот работает как прежде,
только с локальной копией. После одноразовой OAuth-авторизации на сервере
создаётся секретный файл токена; он не попадает в GitHub. При включённом Drive
бот сначала сохраняет документ на сервере, а затем загружает его копию в
Google Drive. Если Drive временно недоступен, клиентский документ остаётся на
сервере, а бот честно сообщает об этом в чате.

## Автозапуск на сервере

Готовый unit находится в `deploy/mortgage-ai.service`. Он запускает бот от
отдельного пользователя `mortgageai`, автоматически перезапускает процесс при
сбое и применяет закрытую маску файлов `0077`. Установка выполняется от root:

```bash
cp /opt/mortgage-ai/deploy/mortgage-ai.service /etc/systemd/system/mortgage-ai.service
systemctl daemon-reload
systemctl enable --now mortgage-ai.service
systemctl status mortgage-ai.service
```

Логи доступны через `journalctl -u mortgage-ai.service`. Перед включением
службы ручной `python bot.py` должен быть остановлен, иначе два процесса будут
конфликтовать за один Telegram-токен.

### Состояние на 19 августа 2026

Предыдущая серверная версия успешно прошла тест Google Drive. На время локальной
разработки серверный экземпляр остановлен, чтобы два процесса с одним
Telegram-токеном не конкурировали за сообщения. После переноса обновления бот
снова будет запускаться вручную командой `python bot.py`; следующий технический
шаг — оформить его как службу `systemd`, чтобы он переживал перезагрузку VPS и
самостоятельно перезапускался при ошибке.

Локально проверена новая тихая схема: автоматическое создание сделки,
служебные сообщения только в `Mortgage Notifications`, русские имена папок,
обратная связь с немедленной отправкой оценки и OCR доверенности/СНИЛС.
Изменения ещё предстоит перенести на VPS и повторно проверить с Google Drive.

Никогда не отправляйте токен в чат и не добавляйте его в код. Перед отправкой
изменений в GitHub нужно проверять, что в коммит не попали секреты и документы
клиентов.

## Мониторинг ставок в Telegram-каналах

Обычный Telegram-бот не может читать историю произвольных публичных каналов.
Поэтому мониторинг запускается отдельным локальным процессом от выделенного
Telegram-аккаунта. Получите `api_id` и `api_hash` на `my.telegram.org`, затем
добавьте в `.env`:

```text
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=локальный_секрет
NEWS_CHANNELS=channel_one,channel_two
```

Первый запуск попросит номер телефона и код Telegram и создаст локальный файл
сессии в `data/`. Этот файл и ключи нельзя отправлять в GitHub. Запустите
читатель в отдельном окне Терминала:

```bash
source .venv/bin/activate
python news_reader.py
```

Читатель загружает последние 100 постов каждого канала и продолжает ждать
новые. Найденные упоминания ипотечных ставок сохраняются локально в
`data/mortgage_news.sqlite3`. В боте доступны команды только для команды:

- `/rates` — последние найденные ставки по каналам и программам;
- `/rate_changes` — числовые изменения ставок за последние 7 дней.

Это мониторинг публикаций, а не официальный расчёт предложения: итоговые
условия, надбавки и требования всегда нужно сверять с банком. Первая версия
извлекает явные проценты правилами и не отправляет тексты во внешние AI-сервисы.

## Зафиксированный результат на 12 августа 2026

- Бот проверен в Telegram: создаёт сделку, сохраняет документы от клиентов и
  пропускает документы Андрея и Анастасии.
- Клиент в личном чате может оставить оценку и комментарий; отзыв приходит
  руководителю в личный чат с ботом.
- Распознавание документов работает локально через Tesseract: паспорт,
  СНИЛС, 2-НДФЛ, свидетельства о заключении/расторжении брака и о рождении.
- Неопознанные документы не блокируют работу: они сохраняются под исходным
  именем для ручной проверки.
- Следующая продуктовая задача: карточка комплекта документов и статус сделки.

## Мониторинг новостей банков — первый прототип

Добавлен отдельный локальный модуль для чтения выбранных **публичных**
Telegram-каналов. Он ищет упоминания ипотечных ставок и сохраняет их в
локальную служебную базу. В основном боте для руководителя и менеджера
доступны команды:

- `/rates` — последние найденные упоминания ставок;
- `/rate_changes` — изменения ставок за последние 7 дней.

Для запуска мониторинга в отдельном окне Терминала нужны локальные настройки
в `.env`: `NEWS_CHANNELS`, `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Они не
попадают в GitHub. Команда запуска:

```bash
python news_reader.py
```

Это ранний прототип: сообщения являются информацией из указанных каналов, а
условия банков необходимо перепроверять в официальных источниках или у банка.
